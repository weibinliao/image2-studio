# 图片模型管理设计

日期：2026-07-29

## 目标

- 管理员按渠道读取上游模型，并且界面只展示图片模型候选。
- 管理员可以逐个真实测试候选模型，测试不会修改线上生成配置。
- 测试成功后，管理员通过独立的“设为默认”命令把模型固定到对应生图引擎。
- 保存模型时只修改目标引擎的 `model`，不修改渠道池、成员可见性、自动路由优先级或其他引擎。
- 设置页运行状态按引擎显示当前模型，不再把旧的全局 `IMAGE2_MODEL` 描述成所有引擎的默认模型。

## 管理员流程

设置抽屉新增“图片模型管理”区域：

1. 选择一个已启用渠道。
2. 页面通过 `GET /api/models?channelId=...` 读取该渠道模型。
3. 模型下拉框只显示 `candidateModels`，不回退显示普通文本、TTS 或其他非图片模型。
4. 选择图片模型后点击“测试生图”。测试仍使用现有 `POST /api/test-model` 和渠道对应的适配器。
5. 测试成功后才启用“设为默认”。
6. 管理员选择目标引擎并确认保存。目标引擎必须与渠道协议一致，且该渠道属于目标引擎的渠道池。
7. 保存成功后刷新引擎配置、运行状态和生成区提示。

当前 Gemini 渠道返回 13 个模型，名称筛选得到以下 4 个图片候选：

- `gemini-2.5-flash-image`
- `gemini-3-pro-image`
- `gemini-3.1-flash-image-preview`
- `gemini-3.1-flash-lite-image`

候选名称只说明上游列出了模型。是否能生图仍以真实测试结果为准。

## 不中断策略

- 打开设置、读取模型和模型测试都不修改现有引擎配置。
- “设为默认”使用目标引擎级更新，不整份覆盖 `imageEngines`。
- 保存前校验引擎存在、模型非空、渠道存在、渠道属于引擎且 `providerType` 一致。
- 保存失败时保留原模型，不进行部分写入。
- 正在运行的任务继续使用任务开始时解析到的模型；新模型只影响保存完成后的新任务。
- 不自动切换成员模型，不因某次测试成功而隐式上线。

## API

保留：

- `GET /api/models?channelId=...`：返回 `candidateModels`；管理界面只消费这个字段。
- `POST /api/test-model`：通过选定渠道真实生图，不改配置。

新增：

- `PATCH /api/admin/image-engines/:id/model`

请求体：

```json
{
  "model": "gemini-3.1-flash-image-preview",
  "channelId": "channel-id"
}
```

响应返回更新后的目标引擎。服务端只替换该引擎的 `model` 字段，并使用现有原子设置写入逻辑保存。

## 界面状态

- 未选择渠道：模型列表为空，测试和设为默认禁用。
- 没有图片候选：显示“上游列出了 N 个模型，但没有识别到图片模型”。
- 选择候选但未测试：允许测试，设为默认禁用。
- 测试失败：显示上游错误，设为默认保持禁用。
- 测试成功：显示成功使用的渠道和模型，启用设为默认。
- 模型或渠道改变：立即清除上一次测试成功状态，防止把未测试组合上线。
- 保存成功：目标引擎卡片、运行状态和生成区提示同步显示新模型。

## 运行状态

启用多引擎配置后，设置页不再显示单一的“默认挂载模型 gpt-image-2”，改为逐引擎摘要，例如：

- `GPT：gpt-image-2`
- `Gemini：gemini-3.1-flash-image-preview`

只有没有 `imageEngines` 的旧版单渠道模式才显示全局 `IMAGE2_MODEL`。

## 测试

- 适配器测试：OpenAI 和 Gemini 模型列表都只把图片模型放入 `candidateModels`。
- API 测试：目标引擎模型定向更新；渠道不属于引擎、协议不匹配、空模型和成员请求均被拒绝。
- UI 测试：渠道切换加载图片候选；不显示非图片模型；测试成功前不能保存；更换模型会重置测试状态。
- 回归测试：保存模型不改变 `channelIds`、优先级、启停状态或其他引擎。
- 验收：`npm run check && npm test`，然后在桌面和窄屏设置抽屉验证完整流程。
